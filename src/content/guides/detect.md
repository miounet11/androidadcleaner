检测只读：它读取手机状态并给出报告，不拨任何开关、不挂起任何包。第一次用建议都先跑一遍。

## 检测会读出什么

| 项目 | 说明 |
|---|---|
| 型号与系统 | `ro.product.model`、`ro.build.display.id`，决定匹配哪份机型脚本 |
| 机型脚本 | 是否有同型号脚本；版本号对不上时提示会走安全模式 |
| 快应用中心 | 是否存在、是否已关闭 |
| 广告组件 | `com.miui.systemAdSolution`、`com.opos.ads` 等系统广告包是否存在 |
| 通知渠道 | 各 App 的营销通知渠道数量，供后续按渠道关闭 |

## 命令行

```bash
python3 tool/run.py devices              # 列出已连接设备的序列号与型号
python3 tool/run.py -s <序列号> check     # 只读检测
```

`check` 不会写入任何内容。如果检测都失败，说明连接或权限有问题，先解决连接再谈改动。

## 客户端

打开客户端 → 插线 → 点「检测」。结果以卡片形式列出，**版本不匹配**的条目会标黄，提示该机型脚本可能不适用。

## 版本号对不上意味着什么

机型脚本按 `ro.build.display.id` 的开头比对。例如小米脚本要求 `OS4.0`，你手机上如果是 `OS4.0.27` 就匹配；如果是 `OS3.0.x` 就不匹配。

不匹配时引擎进入 **安全模式**：

- 只执行能确认存在的入口，找不到就跳过；
- 不会盲点屏幕上相似但不相同的按钮；
- 执行后提示「部分完成」，并列出跳过的步骤。

安全模式不是降级，它是刻意的保守策略 —— 少关一个开关，好过点错一页设置。

## 检测通过之后

1. **先备份**：`backup` 生成改动前快照，见[改动前备份](/guides/backup)。
2. 再执行：`recipe` 跑机型脚本，或按[手动清单](/guides/manual-checklist)逐项操作。

## 报告里值得注意的字段

**系统版本与构建号**：这两个一起决定了设置页长什么样。同一个机型刷了不同地区的固件，入口名称也会不同。

**通知渠道数量**：数字大不代表要全关。工具会排除订单、快递、付款、日程这类服务通知，只把营销类列出来。

**快应用状态**：很多用户以为广告是浏览器弹的，其实是快应用。见[快应用是什么](/guides/quickapp)。
