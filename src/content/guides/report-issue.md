维护者看不到你的手机。「不行」「失败」「还是不行」这类描述无法定位问题。这份清单帮你在一次往返里说清。

## 必须提供

| 信息 | 从哪里拿 |
|---|---|
| 机型与构建号 | `check` 输出，或设置 → 关于手机 |
| Android 版本 | 同上 |
| 工具版本 | 客户端关于页，或 `--version` |
| 执行的命令 | 原样粘贴 |
| 完整报错 | 客户端「复制完整诊断」，或 `logs/last-error.txt` |
| 失败发生在哪一步 | 段名或界面上的步骤标题 |

## 完整诊断里有什么

- 首个 `Exception` / `Caused by` 与完整堆栈；
- 系统版本、构建号；
- 已脱敏的序列号与用户目录路径。

它**不包含**：账号信息、手机号、通知内容、已安装应用列表。

## 好例子

```
机型：Xiaomi 18 Pro Max (M154FF)
构建号：OS4.0.24.0.WNCCNXM
Android：17
工具：0.2.3 (Windows)
命令：python run.py -s 9xxxxxx recipe
现象：第 3 段「应用商店」在 find_click("服务管理") 处返回 not found
诊断：（附完整报错）
手动验证：我在手机上能找到「服务管理」，在同页需要先滚动一次才可见
```

## 差例子

- 「点了没反应」——哪个按钮、什么反应？
- 「广告还在」——哪个 App 的哪条广告？系统广告还是推送？
- 「小米手机用不了」——哪个型号、哪个版本？
- 只贴截图最后两行。

## 隐私提醒

贴日志前自己扫一眼，删掉序列号、手机号、账号名。虽然工具会脱敏，但你自己截的图不会。

## 反馈后

维护者可能需要你补跑一个命令或提供某个页面的控件树：

```bash
python3 tool/explore.py -s <序列号> --dump-page > page.txt
```

这个输出包含当前页面的控件文字，**可能包含个人信息**，提交前检查。
