「去广告要 root」是十年前的印象。现在大部分系统广告都有官方开关，只是藏得深、分散。工具做的是替你把这些开关逐个拨到正确位置。

## adb 能给什么权限

| 能力 | 说明 |
|---|---|
| 读取界面 | 拿到当前页面的控件树与文字 |
| 模拟点击 | 点开关、切页面 |
| 修改通知渠道 | 关闭单个营销渠道 |
| 挂起应用包 | `pm suspend`，可逆 |
| 读写部分系统设置 | `settings put`，限部分命名空间 |

## adb 做不到什么

- 修改 system / vendor 分区；
- 卸载系统应用（`pm uninstall` 需要更高权限，且工具不使用）；
- 拦截网络请求（需要 root 层 VPN 或 hosts）；
- 修改已安装 App 的代码。

## 与 root 方案的区别

| 方案 | 原理 | 风险 | 可逆 |
|---|---|---|---|
| 本工具 | 拨官方开关、挂起包 | 低，系统更新不受影响 | 完全可逆 |
| Magisk 模块 | 修改系统文件或注入进程 | 中，可能影响 OTA | 需卸载模块 |
| 刷机 / 定制 ROM | 替换整个系统 | 高，保修、银行 App 校验 | 需回刷 |
| hosts 去广告 | 拦截域名 | 中，可能误伤正常服务 | 可逆 |

root 方案能做的更多（比如彻底拦截广告 SDK 的网络请求），但对多数人来说，「系统设置里那些开关全关掉」已经解决了大部分可见广告。

## 不 root 的边界

以下广告工具处理不了：

- **App 内嵌广告**：比如新闻 App 信息流里的原生广告。这不是系统广告，工具不碰。
- **视频前贴片广告**：同上。
- **服务端下发且无开关的推广**：少数新版本会把开关藏到服务端控制，只能等厂商给出口。
- **原生鸿蒙 NEXT**：不走 adb，无法连接。

## 安全性说明

工具做的是「模拟你手动点」这一件事。它不会：

- 上传任何数据（没有联网上报，日志只存本地）；
- 读取短信、通讯录、相册；
- 截取账号页或手机号页（遇到会跳过）；
- 替你同意任何协议（遇到协议页点取消）。

源码在 [GitHub](https://github.com/miounet11/android-ad-cleaner) 上，可以自己审。

## 保修与官方态度

adb 调试是 Android 官方提供的开发者功能，使用它不会使保修失效，也不修改系统完整性校验。厂商官方客服通常也会建议用「关闭个性化推荐」的方式减少广告。
